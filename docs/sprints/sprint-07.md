# Sprint 7 — Payroll core and the India pack

Status: **Complete, awaiting owner approval** · Date: 2026-11-27 · Branch: `sprint-07/payroll`

## 1. Objectives
A country-neutral payroll engine that pays people correctly, explains every number and cannot be changed once finalized, plus the first native country pack: **India** (chosen by the owner this sprint). Statutory rates live in versioned rule data, never in code. A payroll run moves through maker-checker approval to immutable payslips and a bank file.

## 2. Scope
**In:**
- **Engine** (`packages/payroll`):
  - decimal.js arithmetic on string amounts; no floating point anywhere;
  - a safe formula language (no `eval`) with MIN/MAX/ROUND/FLOOR/CEIL;
  - fixed / percentage / formula / statutory / input components;
  - per-component rounding;
  - two passes: the full month for CTC balancing, then actual pay prorated by paid days;
  - a calculation trace on every line;
  - errors instead of silent zeros.
- **India pack** (`packs/in.js` with rule data in `rules/in.js`, FY 2025-26):
  - **PF:** 12% employee and employer on wages up to ₹15,000 or on actual wages; EPS split; EDLI and admin charges.
  - **ESI:** 0.75% / 3.25% up to ₹21,000 gross, rounded up.
  - **Professional Tax:** Karnataka; Maharashtra including the exemption for women; the February amount.
  - **TDS:** new regime (₹75k standard deduction, slabs, s.87A rebate up to ₹12L with marginal relief, surcharge, 4% cess); old regime with standard deduction, PT and capped 80C/80D/80CCD(1B)/24(b); monthly projection with year-to-date from finalized runs; taxable income rounded to ₹10.
- **Rule versions:** seeded into `statutory_rule_versions` with a SHA-256 checksum. A published version can't be changed (the seed refuses), and each run pins the version it used. `reviewed_by` stays empty until an in-country expert signs off; the UI says so on every run and on the statutory settings page.
- **Configuration:** components; structures with an order and reference check; a one-click India starter structure; statutory settings per legal entity from a date (PF/ESI switches, PF wage components, PT state, registration numbers); payroll settings (calendar or 30-day month, absence as loss of pay, pay day).
- **Salaries:** effective-dated CTC per employee; sensitive and audited (including views); a live monthly breakdown preview.
- **Runs** (PAY-03..05):
  - **Lifecycle:** `DRAFT → INPUTS_LOCKED → CALCULATING → CALCULATED → REVIEWED → APPROVED → FINALIZED → PAID`, with back to draft, send back and cancel before finalizing.
  - **Maker-checker:** the reviewer can never approve.
  - **Locking inputs** also locks the period's attendance; leave decisions inside a locked period are refused.
  - **Calculation** runs in the worker.
  - **Loss of pay** comes from approved unpaid leave, days before joining or after leaving, and (optionally) absences.
  - **Inputs:** variable pay and reimbursements.
  - **Finalizing** stores a hash of every amount; database triggers then refuse any change except marking the run paid.
  - **Outputs:** payslip PDFs generated by the worker into private storage; register CSV; variance against the previous finalized run; bank transfer CSV (account numbers decrypted only for the download, audited, missing accounts reported).
- **Self-service:** My payslips (60-second download links); tax declaration (regime and deductions, verified by payroll).
- **UI:** Payroll settings, the Salary tab on the employee profile, Payroll runs (list, run detail with stepper, totals, results with line traces, inputs, variance, downloads, the tax declarations review tab), My payslips.

**Out:**
- More Indian states' PT; LWF; gratuity provisioning; surcharge marginal relief; senior-citizen slabs; HRA exemption calculation; perquisites; Form 16 / 24Q / ECR and other statutory filing files (PAY-06, L).
- Salary revisions with arrears and mid-month salary changes: the salary in force at the end of the period applies.
- F&F settlement, off-cycle and adjustment runs (schema ready).
- UK and other native packs; configurable mode is available for every country.
- Bank-specific file formats (NEFT bulk, SEPA, BACS): a generic CSV for now.
- Unicode fonts in payslips: standard PDF fonts cover Latin-1; other characters are replaced. The currency is printed as its code.

## 6. Backend implementation
- `packages/payroll`: `money.js`, `formula.js`, `engine.js`, `packs/in.js`, `rules/in.js` (data), `templates.js` (the India starter).
- `modules/payroll/config.service.js`:
  - rule version lookup;
  - statutory settings validated by the pack's schema;
  - structure checks (a formula may only use components above it; statutory items must exist in the country pack);
  - salaries; preview; tax declarations.
- `run.service.js`:
  - state transitions as atomic `UPDATE … WHERE status = current`, with permission checks;
  - attendance lock and unlock;
  - loss of pay and paid days; year-to-date from finalized runs;
  - per-employee calculation, inside one transaction, with pinned rule versions;
  - the result hash; register, variance and bank file;
  - payslip generation (idempotent).
- `payslip-pdf.js`: a one-page A4 payslip with pdf-lib.
- Leave: decisions and cancellations inside a locked payroll period return `period_locked`.
- Worker: `payroll-calculate` and `payroll-payslips` jobs.
- Docker: backend and worker images include `packages/payroll` (verified by building both and loading the engine in the image).

## 7. Frontend implementation

  - the run page: a progress stepper; actions limited by status and permission; maker-checker explained; totals; results with expandable lines and "How" traces; inputs while in draft; variance; register and bank file downloads;
  - a tax declaration review tab.
- **My payslips:** list, download, and the tax regime / deductions form.

## 11. Review
**Problems found and fixed during the sprint**
1. **Silent zero in the engine:** a formula error in a prorated earning was caught in the first pass, then lost, because the second pass only prorates the first pass's (zero) result. The error is now kept from both passes. A golden test caught it.
2. **Leave could change a locked payroll period:** the first guard only checked locked attendance rows, so days without a clock-in weren't protected. It now checks for a locked payroll run covering the dates (covered by a test).
3. **UK shown as "native payroll"** in the seed although no UK pack exists. Corrected to configurable.
4. **"Add employee" could submit before the legal entity loaded** (Sprint 4 form). Under load the default legal entity arrived after a fast click and the API correctly returned 422. The E2E suite exposed it in 2 of 12 runs, and the API log showed exactly two 422s on employee creation. Create is now disabled until reference data loads, and the default is applied at submit. No 422s and no failures in 5 full runs since.
5. **E2E sign-in rate limit:** with seven journeys in parallel from one IP, the per-IP limit (60 a minute) correctly returned 429. The local E2E API now runs with `AUTH_IP_LIMIT_PER_MIN=300` (documented); the production default is unchanged.
6. **Money formatting:** Prisma returns decimals without trailing zeros, so the API normalises amounts to the four-decimal storage format.

**Known limits**
- The FY 2025-26 rule version also applies after 31 March 2026 until a new version is published. FY 2026-27 rates must be published as version 2 (the seed refuses edits to version 1).
- The salary in force at the end of the period is used; mid-month revisions and arrears come later.
- ESI eligibility is checked monthly (the statutory contribution-period rule isn't modelled).
- Only Karnataka and Maharashtra PT are included; other states return "no PT" until added as data.
- `npm audit`: the same 18 moderate, dev-only Jest advisories.

**Demo steps**
1. Settings → Payroll → Structures → Load India starter. Statutory → set the PT state.
2. Employees → a person → Salary → enter a CTC and watch the breakdown → Save.
3. Payroll runs → New run → Lock inputs → Calculate → open a person's lines and "How".
4. Mark reviewed; Approve is refused for you. Sign in as a Finance Manager to approve and finalize.
5. As the employee: My payslips → Download.
